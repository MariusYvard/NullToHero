# NullToHero for Hermes Agent

NullToHero installs on [Hermes Agent](https://github.com/NousResearch/hermes-agent)
as a fifth build target (`hermes`), alongside `codex`, `kimi`, `kimi-plugin` and
the neutral `agents` package — generated by the same
`null-to-hero/tools/build-dist.mjs`. It does not modify `null-to-hero/`, `dist/`
or the Claude Code plugin in any way.

## What is here

- **`tools/convert-agents-to-skills.py`** — converts the 15 Claude Code
  sub-agents (`null-to-hero/agents/*.md`) into standalone Agent Skills. There
  is no Hermes equivalent of a named sub-agent directory (`.codex/agents/`,
  `.kimi-code/agents/`), so `delegate_task` cannot resolve a `subagent_type`
  by name; each sub-agent instead ships as its own skill, and `delegate_task`
  is given a free-text `goal` per task built from that skill's description.
- **`skills/`** — the 15 generated outputs, regenerated on every run of
  `update-hermes-skills.sh` so they stay in sync with `null-to-hero/agents/`.
  Not committed stale: re-run the converter after editing a source agent.

## Why `dist/hermes` is a first-class target, not a bolt-on

The other four packages differ from Claude Code only in tool names and
sub-agent file format. Hermes is the same story: `tools/build-dist.mjs`
carries a `HOSTS.hermes` entry (see `host-tools.csv` and `prose-tokens.csv`
for the token substitutions, e.g. `Task tool` → `delegate_task`), so
`dist/hermes/skills/nth-*` reads exactly like the other targets — Claude's
prose rewritten for Hermes's own tools, `delegate_task` named wherever the
source asks for sub-agent delegation. It is not the neutral `agents` package
with a note bolted on: `HOSTS.hermes.delegates = true` gives it its own text
path in `tools/build-dist.mjs` (`hostNote()`, `hostReadme()`), so the
generated skills say "use delegate_task" rather than "run it yourself" (which
is what the neutral package says, correctly, since it targets hosts with no
delegation tool at all).

## Installation

```bash
bash update-hermes-skills.sh          # from the repository root
```

The script:
1. `git pull` (if the tree is clean);
2. `node null-to-hero/tools/build-dist.mjs` — rebuilds all five targets,
   including `dist/hermes`;
3. regenerates `hermes-agent/skills/` from `null-to-hero/agents/`;
4. `bash install.sh --target hermes` — copies `dist/hermes/skills/*` and
   `hermes-agent/skills/*` into `~/.hermes/skills/` (or `$HERMES_HOME/skills`,
   or `%LOCALAPPDATA%\hermes\skills\` on Windows), substituting `${NTH_ROOT}`
   with the absolute path of this checkout.

For a one-off manual install: `bash install.sh --target hermes` (or
`powershell -File install.ps1 -Target hermes` on Windows) after a build.

For daily automatic sync, schedule this script as a Hermes cron job
(`cronjob` MCP tool, `no_agent: true`) pointing at a wrapper in
`~/.hermes/scripts/`.

## How to dispatch the 15 sub-agents

`nth-audit full` names fifteen sub-agents by `subagent_type` in the Claude
Code source text. On Hermes, dispatch them with `delegate_task`: one call, one
task per sub-agent in the same `tasks` array, so they run as real parallel
sub-agents in isolated contexts — this is not a degraded fallback, it is the
same parallel-and-isolated capability the source text asks for, reached
through Hermes's own delegation tool. `delegate_task` takes a free-text `goal`
per task rather than a named `subagent_type`; use each sub-agent's installed
SKILL.md (from `skills/` here) as the description to paraphrase into that
goal.

## Known differences from the Claude Code plugin

| Aspect | Claude Code | Hermes |
|---|---|---|
| Sub-agent file format | `.md` per agent in `agents/` | none; ported as standalone Agent Skills |
| Dispatch mechanism | `Task` tool, `subagent_type` lookup | `delegate_task`, free-text `goal` per task |
| `${NTH_ROOT}` / `${CLAUDE_PLUGIN_ROOT}` | resolved by Claude Code at runtime | substituted at install time by `install.sh` |
| Where the sub-agent prompts live | `null-to-hero/agents/*.md` (source of truth) | `hermes-agent/skills/*/SKILL.md` (generated, do not edit directly) |

None of these degrade the Claude Code plugin: `null-to-hero/` and `dist/`
(minus the new `dist/hermes/` directory) are unaffected.
